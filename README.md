# MultiLauncher 混合启动器 · 使用说明书

适用版本：**v0.1.8.2** ｜ 平台：Windows 10 / 11（x64）。文中出现的路径、模型名、端口、密钥、版本号均为**示例或占位符**，请以本机实际值为准。

---

## 0. 一分钟认识它

MultiLauncher 是一个**本地大模型启动器**。它把原本要在命令行里做的那些事——选模型、调参数、起服务、看日志、查更新——变成一个有界面的窗口。

它同时管**三个引擎模块**，可以只开一个，也可以都开：

| 模块 | 是什么 | 界面显示名 |
| --- | --- | --- |
| Strata | 内置的 Strata 推理引擎（模型扫描、服务启停、网关路由） | Strata |
| llama.cpp | 标准的 `llama-server` | llama.cpp |
| Ninfer | 另一套推理引擎，分**两个后端**：WSL（虚拟机里）与 WIN（本机原生） | Ninfer |

三个模块**互不干扰**，各有各的页面、各有各的配置、各有各的更新通道。停用某个模块 = 它在界面上**完全消失**（不扫模型、不探活、不起进程）。

---

## 1. 它是干什么的

- **选模型**：从下拉里挑一件，界面上方的参数会自动换成**这件模型自己那份**。
- **调参数**：上下文长度、KV 精度、投机解码、视觉、显卡……改完点「保存」落盘。
- **起服务**：点左栏「启动」，引擎起来后日志里会打一行 `已就绪`，状态灯转绿。
- **看日志**：引擎的输出全进日志框，按模块分流显示。
- **查更新 / 回退**：一键检查上游新版本、下载、升级；升级前自动备份，随时能退回去。
- **当网关用**（路由模式）：让客户端只连一个端口，启动器按请求里的模型名自动唤醒对应的模型。

**它不做什么**：

- 不接管几十 GB 的模型下载（装模型走官方 SETUP，启动器只负责「配置新模型」那一下）。
- 不改引擎本身的源码与配置模板（除「升级」会覆盖源码这一支）。
- 不做官方标注为实验性的功能。

## 2. 装在哪、怎么跑起来

### 2.1 目录长什么样

启动器是**自包含**的——整个目录删掉就能重来，所有设置与配置都在自己这一层里：

| 路径 | 说明 |
| --- | --- |
| `MultiLauncher.exe` | 启动器本体（单文件，旁边没有 .pdb） |
| `MultiLauncher.ini` | 启动器自己的设置 |
| `logs/` | 日志文件（勾了「写入日志文件」后才有） |
| `data/config/llama/llama_models.ini` | llama 的配置本体 |
| `data/config/ninfer/ninfer_models.ini` | Ninfer 的配置本体 |
| `data/config/strata/` | `<模型名>.json` + `<模型名>.shared-settings.json`（**产物**，每次启动前重建） |
| `data/backup/llama/` | llama 的配置备份 |
| `data/backup/ninfer/` | Ninfer 的配置备份 |
| `data/backup/ninfer-exe/` | Ninfer 的引擎 exe 备份（二进制单独一格） |
| `data/backup/strata/` | Strata 的配置备份 |
| `data/tmp/` | 草稿窝：更新链的解压中转、自检副本；超 3 天的残留自动清 |

Strata 侧还有它**自己的数据目录**（模型、编译产物等），那个目录**启动器只读**，不往里写东西。

### 2.2 启动与退出

- **双击 exe** 即可运行，不需要安装。
- 点窗口右上角 **✕ 只是缩到托盘**（可在设置里关掉这个行为）；真正退出走**托盘菜单 →「退出」**。
- 勾了「随系统启动」的话，登录 Windows 后会自动运行；再勾「启动时隐藏到托盘」就保持后台常驻、不弹窗。

## 3. 界面总览

主窗口分成四块：**左栏**、**页头**、**主区**、**底部状态栏**。

### 3.1 左栏（当前模块的上下文）

从上到下：

| 位置 | 内容 |
| --- | --- |
| 启停按钮 | 文案会跟着当前状态变：服务在跑 → 「停止」；端口上是外部拉起的服务 → 「停止」（会先确认）；只剩网关 → 「停止网关」；都没有 → 「启动」 |
| 运行状态卡 | 状态灯 + 文字，含**版本**一行（行末有一枚小更新按钮） |
| 模式条 | 点一下切换**路由模式 / 单体模型**（两个模块各自记忆） |
| API 地址 | 给别的程序填的 base URL：`http://<地址>:<端口>/v1` |
| 模块状态 | 常驻显示**所有启用模块**的灯：灰=没在跑 / 绿=就绪 / 橙=在跑但待机 / 红=异常 |

### 3.2 页头与主区

页头是**分段按钮**：每个启用的模块各占一格（Strata / llama.cpp / Ninfer）。**点格切页，切页只是换视角，不动服务。**

主区每页三张卡：

- **参数卡**
  - 卡 1：`监听地址 ｜ 监听端口 ｜ 思考深度 ｜ 保存`
  - 卡 2：`模型名称 ｜ 上下文 ／ KV 精度 ｜ 附加参数`
  - 右侧按钮列：「打开网页」「高级」（展开后随激活模块切换内容）
- **模型卡**：模型下拉 + 加载/卸载按钮（下拉里带绿色「已加载」标记与灰色估算占用）
- **日志卡**：本模块的日志；「清屏」只清当前页显示

### 3.3 底部状态栏

服务在跑时出现，可显示**九档**数值，每档可单独勾选：

`预填充 ｜ 解码 ｜ MTP 接受率 ｜ 队列 ｜ 缓存命中 ｜ 输入 ｜ 输出 ｜ 显存 ｜ 温度`

- **平均 vs 当前**：只有「预填充」与「解码」两档有「平均」这一枚，且**与「实时」各自独立**——只勾平均 = 只出平均值。
- **取不到的档显示短横 `-`**（不写单位）。
- **次序可拖**：在设置页里按住某一格横着拖，拖出来的先后就是底部那条串的先后。
- **显存 / 温度是整卡值**（不是逐进程），三页显示同一个数。

## 4. 三个模块怎么用

### 4.1 Strata

- **家底**：`<Strata 目录>/strata-<模型名>.json` 是**模板**（启动器只读）；你在界面上改的参数记在 `MultiLauncher.ini` 的 `[Model:<模型名>]` 段里。
- **生效配置**：`data/config/strata/<模型名>.json` 是**产物**——每次启动前按「模板 + 你那段」重建。**在这份产物上改，下次启动就没了。**
- **要长期改**：改模板，或在界面上改完点「保存」。
- **「打开配置」按钮**：开的是 `MultiLauncher.ini` 本身（你「保存」写的就是它、远端唤醒读的也是它）。
- **上下文调超训练长度**时，启动器会自动补 `--rope-scaling yarn` 与 `--rope-scale <因子>`，并顺手打开 `fit_max_tokens`（长提示 + 大输出上限时截断而不是报 400）。这两个不是独立旋钮，是「上下文」这个数的机械后果。

### 4.2 llama.cpp

- **家底**：`data/config/llama/llama_models.ini`。**界面上「保存」写的就是它、引擎读的也是它**——同一份文件，没有「两份要对齐」这件事。
- **一个文件多段**：每个 `[模型名]` 段就是一件模型。**留空 = 从这个段里删掉这个键 = 回到继承**（读序：本段 → `[*]`/文件头 → 引擎默认）。
- **模型行的按钮**：这一页**有东西加载着就一直给「卸载」**，点它卸的是**实际在加载的那一件**（不必先把下拉指过去）；一件都没加载才写「加载」。切件 = 先卸载再加载。
- **单体模式**下按钮变「重载」= 按当前界面参数重新加载。
- **速度提醒**：`parallel` 这一键启动器不替你定。不给时引擎走 auto = 4 槽 + 统一 KV，**本机实测比 `parallel = 1` 慢很多**。要那个速度，就在段里（或 `[*]` 里）写 `parallel = 1`，或在卡 2「附加参数」填 `--parallel 1`。启动器只在日志里提醒一行，**不替你改家底**。

### 4.3 Ninfer

**一个模块、两个后端**：WSL（虚拟机里那份引擎）与 WIN（本机原生 exe）。界面上叫 WSL / WIN。

- **卡 1 左侧那枚方块 = 后端选择**：当前那枚居中，底下露一条边提示「还有另一个」，点一下轮换。
- **起哪一条链由「段里那一枚 `backend`」说了算**：客户端请求的是 WIN 那件，就用 WIN 那条环起来，方块、下拉与参数格一起切过去。
- **只留「按需唤醒」这一档**：启动器守**公开端口**，引擎绑**内部端口**；没请求就停服还显存，下次请求自动起（本机约 9 秒 / WSL 约 15 秒）。所以这一页**没有模式条**。
- **左栏「启动」= 只把网关立起来**，不加载模型、不占显存。模型有两个入口：① 客户端发第一个 `/v1` 请求；② 卡 3 的「加载」。
- **家底**：`data/config/ninfer/ninfer_models.ini`。一个段 = 一件模型，段名 = 对外的 model-id；段里 `backend` / `file` 两个键 + **其余一行一键**。**布尔项「关」= 删掉那个键，不会写 `= false`。**
- **启动器不新建段、不改段名、不删段**——要加新件，自己往文件里补一段。
- **非法值不拦你输入，但会在起服务前拒绝启动并说清为什么**（例如：共享前缀上限必须为 0、WIN 的上下文必须大于设备池、swift 件不能配行粒度 KV、分块预填充不能大于 4096、主机缓存不能大于 16384）。
- **WSL 后端默认关着**：开着它每次启动都要扫一遍虚拟机（会把 VM 拉起来）。要用就在设置页里打开，并核对发行版名、VM 内模型目录与引擎路径。
- **这一族没有引擎自带的网页界面**，所以这一页不放「打开网页」。

## 5. 两种启动模式

左栏那根模式条点一下切换（**两个模块各自记忆**）：

| | 路由模式 | 单体模型 |
| --- | --- | --- |
| 点「启动」做什么 | **只立网关**，不加载模型 | 起服务**并**加载选中模型 |
| 谁监听公开端口 | 启动器自己的网关 | 引擎自己 |
| 模型什么时候加载 | 第一个推理请求到达时，按请求里的模型名 | 点启动时 |
| 一次驻留几个模型 | 一个（切模型 = 停旧起新） | 一个 |

**路由模式下**：

- `GET /v1/models` 由网关自己回答（列出全部已就绪模型），**不加载任何模型**。
- **只有推理请求唤醒模型**（`/v1/chat/completions`、`/v1/completions`、`/v1/messages`、`/v1/embeddings`、`/v1/rerank`、`/v1/responses`）。`/metrics`、`/health` 这类路径**不唤醒**——免得监控轮询把刚空闲停掉的模型又吵起来。
- 请求里的 `model` 对不上任何配置 → **400** 并列出可用模型名。
- **唤醒按「那一件自己的存档」取参，不按界面上此刻显示的值。** 换句话说：**「保存」= 让远端用上新参数的唯一动作。** 你自己点「启动」或「加载」照旧按界面上的值起。
- 上游起不来的落点分两种：**你点按钮** → 当场弹框说清原因；**请求从公开口进来** → 只写一行日志，并把同一句话原样回给客户端（503 / 504）。

## 6. 设置页

设置窗 = **通用 / 每个启用模块各一节 / 关于**（停用模块其节整节消失）。

**生效时机**：所有项都点「保存」才生效并落盘；点「取消」丢弃全部改动。

### 6.1 通用

| 组 | 项 |
| --- | --- |
| 模块 | 三个模块的启用开关（**至少启用一个**；关掉前要先停掉它的服务，保存时会拦下） |
| 启动行为 | 随系统启动 / 启动时隐藏到托盘 / **自动启动服务 ·（每模块一个）** / 就绪后打开网页 |
| 接口 | **API Key**（三模块共用一枚） |
| 显存 | **显存互斥处理**（进入队列 / 返回报错）、**排队等显存上限(秒)** |
| 关闭行为 | 关闭到托盘 / 退出时停止服务 |
| 日志 | 写入日志文件 / 调试信息过滤 / 显示状态栏（+ 一排可拖动的子选项） |

**API Key**：设了之后客户端要带 `Authorization: Bearer <key>`（Ninfer 也认 `x-api-key`）才能调用；留空 = 不鉴权。启动器自己的探活会带上它，所以设了不影响状态灯与就绪判定。已知口径：路由模式下网关**本地回答**的 `GET /v1/models` 不校验它（只有推理路径受保护）。

**显存互斥处理**：一张卡上任一时刻只能有一件把模型读进显存。

- **进入队列** = 请求进来时排队等显存，排到超时回 504 并说清前面是谁。
- **返回报错** = 立刻回 503 并说清谁占着。
- 你自己点「启动」/「加载」那一档**永远是当场拒绝并点名**，与这里选的无关。
- 启动器**不替谁停那一件**——让位归「卸载」/「停止」或它自己的空闲停服。

### 6.2 模块节

每一节的「维护」组固定是同一个形状：**更新源 → 版本 → 回退 → 各自模块独有**。

| 模块 | 这一节有什么 |
| --- | --- |
| Strata | 路径（Strata 目录 / 模型配置目录）、运行（内部端口 / 空闲停服）、维护（更新源 / 版本 / 回退到备份 / 配置新模型）、内建 llama.cpp |
| llama.cpp | 路径（llama.cpp 目录 / 模型配置 / 模型目录）、运行（同时加载上限 / 空闲停服）、维护（更新源 / 版本 / 改动前自动备份） |
| Ninfer | 共用（内部端口 / 模型配置）、WSL 后端（启用 / 发行版 / 模型目录 / 引擎可执行 / 空闲停服）、WIN 后端（启用 / 引擎目录 / 空闲停服）、维护（两条链各自的更新源、版本、回退、备份） |

### 6.3 关于

版本、位置三处（配置文件 / 数据目录 / 日志文件），各带一枚「打开」直达。

## 7. 更新与回退

**一模块一窗**（Ninfer 是一后端一窗），从设置页那节的「更新…」或托盘该模块组的「检查更新」进入。**开窗即自动查一次**，平时不发请求。

窗内三行各一枚按钮：`版本行末尾 跳过/取消跳过`、`检查更新行末尾 查看更新内容`、`第三行 更新`；进度条与取消小 X 只在第三行。

| 模块 | 更新做什么 | 回退 |
| --- | --- | --- |
| Strata | 下载源码包 → **校验内容身份** → 覆盖源码（保留 .venv / engine / 配置模板等）→ 同步官方预编译引擎 | 「回退到备份」：升级前的源码 + 引擎整份快照，**免重编、秒级** |
| llama.cpp | 停服务 → 下包 → **校验体积与 sha256** → 解压成同父目录的新目录 → 切路径 → 问是否删压缩包（**旧目录原样保留**） | 在设置页把「llama.cpp 目录」改回去 |
| Ninfer · WIN | GitHub Release 按本机算力挑资产 → 比体积比 sha256 → **旧 exe 先备份** → **只换 exe，DLL 一律不动** | 「引擎 exe 回退 · WIN · 恢复 exe…」 |
| Ninfer · WSL | 虚拟机里 `git fetch` + 重编（编前会停掉那一侧引擎）；编完自动存一份编译快照 | 「编译快照回退 · WSL」：**免重编、秒级** |

升级中途在「下载 / 解压」阶段可以取消（覆盖与同步引擎那两步不给停，避免留下半新半旧）。

## 8. 备份

| 备份什么 | 落在哪 | 留几份 |
| --- | --- | --- |
| llama 的配置 | `data/backup/llama/` | 最近 3 份 |
| Ninfer 的配置 | `data/backup/ninfer/` | 最近 3 份 |
| Ninfer 的引擎 exe | `data/backup/ninfer-exe/`（**二进制不与配置混排**） | 最近 3 份 |
| Strata 的整份升级快照 | Strata 自己的数据目录下的 `backup/<版本-时间戳>/` | — |

- **每次写配置之前自动存一份**（配置备份），所以「改崩了退得回去」是默认行为。
- Strata 的整份快照**脱离启动器也能恢复**：拷回去就是那一版。
- 老位置的快照**只复制、一个字都不删**——要清理由你自己来。

## 9. 日志

- **界面**：每个模块页只显示「本模块的行 + 启动器自己的行」；未激活页后台照收、切页能看历史；「清屏」只清当前页显示。
- **文件**（勾了「写入日志文件」后）：`logs/launcher.log`、`strata.log`、`llama.log`、`ninfer.log`。**单个文件超 8 MB 滚一次，留 3 份。**
- **「调试信息过滤」只挡界面、不管记录**：日志文件与内存历史里照记（引擎的高频台账会做一条简单的连发去重）。**信号行一条不动**：每个请求的完成行、吞吐量、WARN 与错误、以及启动器自己写的那几行主线索引。
- 界面日志框最多留最近 5000 行。

## 10. 常见问题

**Q：点了「启动」但状态灯一直不绿？**
看日志框最后几行。常见原因：端口被占（日志里会有 `couldn't bind` 之类）、模型文件路径不对、显存不够。Ninfer 还有一档专门的提示——「刚拉起就退，多半是端口被占、显存不够，或件/引擎路径不对」。

**Q：模型下拉是空的？**
该模块没扫到模型。Strata 检查「Strata 目录」；llama 检查 `data/config/llama/llama_models.ini` 在不在；Ninfer 检查 `data/config/ninfer/ninfer_models.ini` 与「引擎目录」。**跑一次 `deploy.ps1` 会自动从仓库补种缺失的那两份家底**（缺才拷，已有不动）。

**Q：改了参数，但引擎还是老样子？**
服务正在跑时用的还是启动那一刻读进去的值。**「停止」再「启动」**（或模型行「加载」，它会先让引擎重读配置）才落到运行中的进程。另外主界面的参数**只有点「保存」才落文件**。

**Q：显存不够，两个模块抢卡怎么办？**
设置页「通用 → 显存」里选「进入队列」（排队等，超时回 504）或「返回报错」（直接 503）。**启动器不会替你停掉别人那一件**——要腾地方就手动「卸载」/「停止」，或等它的空闲停服。

**Q：底部状态栏一直是短横？**
那一档没取到数。状态栏的数据来自引擎的 `/metrics`；服务没在跑时整条会隐藏。某一件没在跑时，对应的实时值自然取不到。显存与温度是整卡值，且**只有勾了那两档才会去问一次**。

**Q：日志太吵 / 想看得更细？**
界面那头归「调试信息过滤」管；文件那头永远记全量（只对高频重复行做一条去重）。要细节就翻 `logs/`。

**Q：更新失败了会怎样？**
校验不通过就**一个文件都不覆盖**，本机保持原样（下载的包按你的选择删或留）。Strata 那支如果源码更新了、引擎没同步成功，日志里会写清楚，可以手动跑 SETUP 或用 `diag/update-engine.bat` 重编。

**Q：Ninfer 换后端时卡了一下？**
切后端要停掉当前那件、把显存还回去，所以会先问你一句。**只把网关立着那一档不会弹确认**（它不停任何东西）。

## 11. 术语表

| 词 | 意思 |
| --- | --- |
| **启动器 / 壳** | 本程序（MultiLauncher.exe） |
| **模块** | 一个可插拔的引擎（Strata / llama.cpp / Ninfer） |
| **后端** | Ninfer 内部的两种运行方式：WSL（虚拟机里）/ WIN（本机原生） |
| **家底** | 你手工编辑、引擎实际读取的那一份配置文件 |
| **产物** | 每次启动前自动重建的生成文件（`data/config/strata/` 那几份），改了下次启动就没 |
| **公开端口** | 客户端连接的那个端口 |
| **内部端口** | 引擎实际绑定的端口（启动器/网关在前台守着公开端口） |
| **路由模式** | 启动器常驻公开端口当网关，按请求里的模型名唤醒对应模型 |
| **单体模型** | 引擎自己占公开端口，点「启动」就连模型一起起 |
| **按需唤醒** | 没请求就停服还显存，下次请求自动起 |
| **空闲停服** | 这么久没有推理请求就停掉服务释放显存（单位：分钟） |
| **显存互斥** | 一张卡上任一时刻只允许一件把模型读进显存 |
| **回退** | 用之前自动存下的备份换回旧版本 |
| **快照** | 一次升级前的完整存档（源码 + 引擎） |
